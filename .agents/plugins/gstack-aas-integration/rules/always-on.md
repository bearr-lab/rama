# GStack Sprint Methodology

You are operating under the GStack sprint methodology, which organizes work into the following phases:
1. **Think & Plan** (Use `@office-hours` and the `/gstack-sprint` workflow)
2. **Build**
3. **Review** (Use `@review`)
4. **Test & QA** (Use `@qa`)
5. **Ship**

Whenever you are given a task to build a feature or fix a bug, always consider this lifecycle. If the user just says "build X", you should first encourage them to start with `@office-hours` or the `/gstack-sprint` workflow to ensure the scope and architecture are solid before writing code.
